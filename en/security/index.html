RGX / Security

Security

Threat model, cryptographic profile, metadata exposure and known limitations of RGX v0.3.

On this pageStatusCryptographic profileProtected informationKnown v0.3 limitationReporting vulnerabilities

Status

RGX v0.3 is experimental software. Private Mode uses established cryptographic primitives, but has not undergone an independent audit and should not yet be treated as a mature replacement for long-established tools in high-risk environments.

Cryptographic profile

PurposePrimitive / parameter
Password KDFArgon2id · 64 MiB · 3 iterations · lanes 1
Authenticated encryptionXChaCha20-Poly1305
Salt16 random bytes per archive
Nonce construction16-byte random prefix + 64-bit frame sequence
Encrypted frame1 MiB plaintext target
Inner integrityBLAKE3 chunk + reconstructed-file digests

Protected information

Private Mode encrypts the complete inner container. Without the password, file contents, names, paths, directory structure, chunk IDs, chunk equality relationships and inner statistics are not directly exposed.

The outer envelope still reveals that the file is private RGX, the public KDF parameters and approximate encrypted size.

Known v0.3 limitation

Temporary plaintext inner container

During private packing and reading, the current reference implementation materializes the inner RGX container temporarily on disk. The temporary directory is removed afterwards, but secure deletion cannot be guaranteed on SSDs, copy-on-write filesystems, snapshots or swap. v0.4 is planned to replace this with encrypted seekable I/O.

Reporting vulnerabilities

Please do not publish exploit details in a public issue first. Use GitHub private vulnerability reporting if it is enabled for the repository.
