Security

Threat model, Recipient Mode, identities, signatures and known limitations of RGX v0.5.0-alpha1.

On this pageStatusCryptographic profileProtected informationIdentities & signaturesLimits & hardeningReporting vulnerabilities

Status

RGX v0.5.0-alpha1 is experimental pre-1.0 software. The implementation uses established primitives, but it has not received an independent cryptographic audit and should not yet be treated as a mature replacement for long-established tools in high-risk environments.

Protected information

Private Mode and Recipient Mode encrypt the complete inner RGX v0.2 container. File contents, names, paths, directory structure, chunk IDs, chunk equality relationships and inner statistics therefore do not appear as plaintext in the outer archive envelope.

Recipient Mode still exposes metadata such as the recipient count, short Key-IDs, whether a password fallback exists, and the approximate encrypted size. Key-IDs contain no names, but as stable identifiers they can create linkability across archives.

Identities & signatures

New RGX v2 identities contain X25519 public material for recipient archives and Ed25519 public material for detached signatures. Private identity files can optionally be protected with Argon2id + XChaCha20-Poly1305.

rgx verify-signature authenticates the exact archive bytes against a trusted RGX public key. Whether that public key really belongs to the expected person or organization still depends on a trustworthy key exchange.

Limits & hardening

Important alpha limitations

A password fallback is only as strong as its password. An unprotected local RGX identity relies on OS account and filesystem protection. Windows-specific hardened ACL handling plus OS keychain, TPM and hardware-token integration remain roadmap work.

Reporting vulnerabilities

Please do not publish exploit details in a public issue first. Use GitHub private vulnerability reporting if it is enabled for the repository.
