RGX / Format

Format specification

Technical overview of the inner container and the RGX v0.3 private envelope.

Two layers

RGX v0.3 consists of the v0.2 inner archive format and an optional v0.3 private envelope. The envelope authenticates and encrypts the complete inner container.

RGX v0.2 inner container

RecordPurpose
RGX\016-byte archive header
CHNKUnique chunk payload + BLAKE3 identity + compression metadata
FILEPath, file digest and ordered chunk references
DIREDirectory path
RGXFFooter statistics and consistency checks

Reference chunking: 64-byte rolling window · 64 KiB minimum · ~256 KiB target · 1 MiB maximum.

Nonce & authentication

nonce = 16-byte random prefix || 8-byte little-endian frame sequence
AAD = 60-byte envelope header || 24-byte frame header

Sequences start at zero, increase by exactly one, and exactly one authenticated final frame is required. Trailing bytes are rejected.

Compatibility

Plain RGX continues to use inner format 0.2. Private RGX uses envelope 0.3 around a complete 0.2 inner archive. Before 1.0, format revisions may intentionally be incompatible.
