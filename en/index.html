Design principles

Three priorities.
One format.

Storage efficiency, privacy and integrity should reinforce each other instead of being separate afterthoughts.

01 / COMPACT

Find repetition. Store it once.

Content-defined chunking re-synchronizes after inserted or removed bytes. Identical chunks across files are referenced instead of stored again.

02 / PRIVATE

Encrypt the structure, not just the files.

Private Mode protects the complete inner container with a password. Recipient Mode encrypts the same stream under a random archive key and wraps it separately for up to 64 X25519 recipients.

03 / RESILIENT

Verify before you trust.

BLAKE3 checks chunks and reconstructed files, AEAD protects encrypted streams, and optional Ed25519 signatures authenticate exact archive bytes against a trusted RGX public key.

Questions

Important context.

Does RGX already replace ZIP or 7-Zip?

Not yet. RGX is functional but remains an experimental pre-1.0 format and has not received an independent cryptographic audit.

How does automatic decryption work?

Recipient Mode searches for a matching RGX identity, by default at ~/.ssh/id_rgx. If its X25519 key matches a recipient slot, RGX unlocks the archive key without an archive password.

Can I still use a password?

Yes. Private Mode remains available. Recipient archives can additionally use --password-fallback to store an Argon2id-based password fallback.
