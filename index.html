Design principles

Three priorities.
One format.

RGX is designed around a simple idea: storage efficiency, privacy and integrity should reinforce each other instead of being separate afterthoughts.

01 / COMPACT

Find repetition.
Store it once.

Content-defined chunking re-synchronizes after inserted or removed bytes. Identical chunks across files are referenced instead of stored again.

file B

02 / PRIVATE

Encrypt the structure, not just the files.

Private Mode protects the complete inner container — including paths, file names, chunk identifiers and metadata — using authenticated encryption.

Questions

Useful context.

Is RGX ready to replace ZIP or 7-Zip?

Not yet. RGX is an experimental pre-1.0 format. It is already functional, but compatibility, security hardening and independent review still need to mature.

Are private RGX archives actually encrypted?

Yes. v0.3 encrypts the complete inner RGX container with XChaCha20-Poly1305 and derives password keys using Argon2id. The implementation has automated security tests but has not been independently audited.

Does deduplication remove my duplicate files?

No. RGX only avoids storing duplicate chunk payloads multiple times inside the archive. During extraction, every original file and path is reconstructed.

Can I send a private .rgx to another device?

Yes. The archive is portable. Install RGX on the other device and use the correct password to list, verify or extract it. Recipient public-key encryption is planned next.
